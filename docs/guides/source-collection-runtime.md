# Source collection runtime

Install HTML/RSS support with `python -m pip install 'noesis-evidence[ingestion]'`. Browser scraping uses the separate `noesis-evidence[browser]` extra, followed by `python -m playwright install chromium` (Linux CI may need `--with-deps`). `noesis doctor` reports missing packages and the corresponding extra. Minimal installations keep these optional.

Crossref and OpenAlex now use native bounded pages. Crossref uses `rows`, `message.items`, DOI identities and publication date parts; `NOESIS_RESEARCH_CONTACT` supplies polite contact information separately from authentication. OpenAlex uses `per_page`, `meta.next_cursor` and reconstructed abstracts; its optional credential is `NOESIS_OPENALEX_API_KEY`. Request credentials are excluded from adapter receipts. Abstract/title-only coverage is explicit. Unsupported request fields fail instead of silently changing the search. See the [Crossref API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/) and [OpenAlex paging contract](https://help.openalex.org/api/paging/).

Run `python scripts/check_scholarly_providers.py --out scholarly-live.json` for opt-in live checks (one page of two records/provider). Successful native fixture tests are separate from timestamped live observations; this is not a guarantee of later availability or every operation. All three scholarly providers returned native records in the recorded live check.

Feed collection persists ETag/Last-Modified and check times in a SQLite sidecar to the subscription file, configurable with `http_state_path`. A 304 is an unchanged outcome, produces no new documents and advances scheduling without contaminating extraction-yield history. Transient feed failures carry Retry-After; harvest retries wait at least that long, or defer values above 60 seconds. This does not certify article-body retries, which still use the existing extraction fallback.

HTTP article discovery resolves relative URLs, strips fragments, deduplicates and restricts links to the configured host. Successful URLs stay deduplicated; a failed HTTP extraction permits one browser attempt in the engine lifetime. Guardian discovery uses a date-shaped article path without a fixed year list. Publication dates remain unknown when absent; collection timestamps are separate and timezone-aware in the Scrapy spiders.

Scrapy live caching now uses RFC2616Policy, a 300-second maximum cache age (configurable 1–86,400 seconds), and excludes 429/500/502/503/504. Browser contexts are owned by the download handler; included pages are closed by callbacks and errbacks. Context/page limits default to two/four with finite configuration ceilings. Content readiness uses a selector with a bounded timeout, without an unconditional sleep. The [Scrapy Playwright lifecycle contract](https://github.com/scrapy-plugins/scrapy-playwright#receiving-page-objects-in-callbacks) requires callers to close included pages. A local Chromium regression exercises six readiness failures followed by successful static and delayed pages; run it with `NOESIS_LIVE_BROWSER=1`.

Optional extruct parses already-fetched structured metadata. Matching article URLs take precedence, followed by other article entities, HTML metadata and visible headings. Candidates and conflicts are retained with locators and a snapshot hash. Canonical URLs are suggestions, not identity-merge authority. Extraction scores explicitly remain heuristic method tiers. Exact body source spans are not supplied by these extraction backends and are labelled unavailable.
