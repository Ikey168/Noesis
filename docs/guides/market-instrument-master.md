# Market instrument master

`MarketInstrumentStore` keeps company, security and exchange-listing identity separate in additive DuckDB tables. Issuers link to an existing Knowledge Graph organization through `kg_entity_id`; the market master does not create duplicate organization nodes. Stable IDs are opaque and are never inferred from ticker symbols.

Each write validates the corresponding Draft-07 contract and appends a revision. Source references retain provider identity, provider revision, content hash, publication and retrieval times, license and entitlement. Dated name, CIK/provider identifier and ticker assertions refer to one of those source references. To end an alias, append the same value with the corrected valid-to boundary. To retract an incorrect alias entirely, append it with `assertion_status="retracted"`; the earlier assertion remains available to requests with an earlier acquisition cutoff.

Use `put_issuer`, `put_security` and `put_listing` to build the identity chain. Multiple security records can share one issuer for separate share classes. A security can have multiple listings for cross-listings. Delist by appending a listing revision with `status="inactive"` and a `valid_to_ms`; the listing and security remain queryable. Record a merger with `put_issuer_relationship(..., relationship_type="merged_into")`, which keeps the old and successor issuers. Universe inclusion and exclusion are versioned through `put_universe_membership` and remain queryable by effective and acquisition time.

`resolve_symbol` performs exact, case-insensitive ticker matching. It accepts an effective `as_of_ms`, an `acquired_by_ms` cutoff and an optional venue MIC. A reuse across non-overlapping validity periods resolves to the correct listing. If more than one current mapping remains, the result is `ambiguous`; if none exists, it is `unresolved`. Both cases create an owner-scoped review item. `list_mapping_reviews` exposes the queue, and `decide_mapping_review` stores a human decision. There is no fuzzy ticker guessing.

For a point-in-time replay, pass `publicly_available_by_ms` as well as the effective and acquisition cutoffs. When a source has no known publication time, it is excluded from a request that supplies this cutoff. If the field is omitted, the response marks that no public-time cutoff was applied; treat it as a current mapping lookup, not a historical reconstruction.

Writes require `market:instruments:write` and namespace write access. Reads require `market:instruments:read` and namespace read/write access. Non-operator calls also need source-specific `market:entitlement:<id>:ingest` or `market:entitlement:<id>:read` scopes. The entitlement ID itself grants no access. Vendor selection, contract rights and live sample coverage remain part of #1655; this module has only fixture-based verification.
