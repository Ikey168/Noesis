# Market price history and session coverage

`MarketPriceStore` accepts normalized `noesis-market-bar-v1` observations and validates them before storing them in additive DuckDB tables. A bar's stable key is provider + listing + interval + start time. The first observation creates revision 1; a provider correction appends another revision and links it to its predecessor. Replaying an identical payload is idempotent.

The store preserves the provider's OHLCV, currency, adjustment basis, public time, retrieval time, provider revision, snapshot/hash and entitlement. All timestamps are UTC epoch milliseconds. Normalize daily bars to the venue session open and close so their local date joins the exchange calendar. The store does not adjust vendor prices or infer missing bars. Reads select a retained revision with explicit acquired and optional public cutoffs. A supplied public cutoff excludes values whose publication time is unknown or later; omitting it performs an acquisition-bounded current lookup and should not be presented as a public-time historical replay.

Trading sessions use `noesis-market-trading-session-v1`. `session_status` records `trading`, `holiday`, `weekend` or `special_closed`; `data_status` independently records `present`, `no_trade`, `missing`, `not_requested` or `unknown`. `coverage()` joins these calendar rows with bars using the listing's IANA timezone. It distinguishes a holiday from a trading session with a missing bar, and a session with no trades from an unobserved date.

`MarketPriceIngestor` runs a provider callback over half-open date ranges `[start_date, end_date)`. The callback maps vendor responses into normalized bar contracts and returns pages with `bars`, `next_cursor` and `done`. Configure `MarketIngestBudget` from the selected provider's terms: requests per minute, requests and records per run, rows per page and maximum backfill days. Each run stores a checkpoint before requesting data and after each page, resumes from the last cursor, and can safely replay a page because an unchanged provider row content hash is idempotent even when it is retrieved again later. A changed row hash appends a correction revision. Local hard limits cap each configured budget.

`FmpEodAdapter` is the selected technical adapter. It calls FMP's non-split-adjusted EOD endpoint in bounded calendar-day windows, normalizes daily timestamps in the listing's IANA venue timezone, applies sourced early-close overrides, retries only bounded transient failures and strips credentials from errors and source URLs. It supports `1d` bars only and labels the provider values `unadjusted`; Noesis corporate-action calculations remain separate. FMP's holiday response has no explicit coverage envelope, so calendar generation fails closed unless the response contains declarations for every requested year. The caller must supply an existing license and entitlement ID: a working API key does not create rights.

For split-aware price-return and cash-dividend total-return series, see the [corporate actions and adjustment rules](market-corporate-actions.md) guide. Adjustments consume raw daily bars and retained action revisions; vendor-adjusted bars are rejected to prevent double adjustment.

Reads require `market:prices:read`; writes require `market:prices:write`, plus the corresponding namespace access. Non-operator operations also require the source-specific entitlement scope. Deterministic adapter and store coverage is supplemented by the payload-free live receipt in `config/market/acceptance_packs/live-price-provider.json`. The supplied FMP credential exposed only partial sample scope and no commercial-rights grant, so this adapter remains disabled for production persistence pending #1655.
