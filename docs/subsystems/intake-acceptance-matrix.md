# Information Intake acceptance matrix

This matrix tracks [the ten-mode milestone](https://github.com/Ikey168/Noesis/issues/1569) and [cross-repo acceptance](https://github.com/Ikey168/Noesis/issues/1583). A session-ledger completion check is a recorded claim, not proof of the user's outcome. The linked mode issues remain open until their own criteria and the representative Modulo journeys pass. "Available" means an operation can be called through the Knowledge Engine MCP surface; it does not imply that a live deployment or a signed-in Modulo Desktop journey was tested.

| --- | --- | --- | --- |

The Noesis object ID/revision is authoritative for acquired sources, evidence, claims, decisions, Noesis-authored artifacts, playbooks, and practice history. Modulo is authoritative for signed-in workspace organization, planning, calendar blocks, and user-edited notes/tasks. A `workspace_links` entry or `export_modulo_intake_handoff` envelope carries a versioned pointer and transition reason; it does not copy or validate a Modulo object. Modulo's signed-in plugin state carries its navigation and exact retry keys. Current access must be rechecked before a linked projection is shown. See [the session and handoff contract](intake-modes.md) and [Modulo #474](https://github.com/Ikey168/Modulo/issues/474).
