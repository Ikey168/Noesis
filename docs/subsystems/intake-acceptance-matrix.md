# Information Intake acceptance matrix

This matrix tracks [the ten-mode milestone](https://github.com/Ikey168/Noesis/issues/1569) and [cross-repo acceptance](https://github.com/Ikey168/Noesis/issues/1583). A session-ledger completion check is a recorded claim, not proof of the user's outcome. The linked mode issues remain open until their own criteria and the representative Modulo journeys pass. "Available" means an operation can be called through the Knowledge Engine MCP surface; it does not imply that a live deployment or a signed-in Modulo Desktop journey was tested.

The Noesis object ID/revision is authoritative for acquired sources, evidence, claims, decisions, Noesis-authored artifacts, playbooks, and practice history. Modulo is authoritative for signed-in workspace organization, planning, calendar blocks, and user-edited notes/tasks. A `workspace_links` entry or `export_modulo_intake_handoff` envelope carries a versioned pointer and transition reason; it does not copy or validate a Modulo object. Modulo's signed-in plugin state carries its navigation and exact retry keys. Current access must be rechecked before a linked projection is shown. See [the session and handoff contract](intake-modes.md) and [Modulo #474](https://github.com/Ikey168/Modulo/issues/474).

## Dedicated-plugin v3 return mapping

The opt-in v3 handoff records workspace, account, plugin, collection, record ID,
authoritative Modulo version, and a separate Noesis object kind/ID/version.
The table names a representative entry for each mode; the complete dedicated
plugin list remains in [#1580](https://github.com/Ikey168/Noesis/issues/1580).
Each row is a *mapping example*, not evidence that the plugin is installed,
populated, or accessible to this caller.

| Mode | Modulo plugin/collection example | Noesis operation and return object | Authority and visible completion |
| --- | --- | --- | --- |
| Awareness | `feeds-reading-inbox/items` | Triage feed item; return intake decision/session revision | Modulo owns original item; Noesis decision is recorded only |
| Exploration | `bookmark-read-later/bookmarks` | Capture source or lightweight session; return source/session revision | Modulo owns bookmark; Noesis trail may end with no output |
| Deep Research | `evidence-library/sources` | Start project, assess bundle; return cited project/bundle revision | Modulo owns library entry; Noesis owns evidence and recorded DoD |
| Decision Support | `decision-journal/decisions` | Write Decision Record; return Noesis decision revision | Journal edits remain Modulo-owned; Noesis rationale is recorded |
| Problem-Solving | `evidence-reproducibility/records` | Record typed trail; return verification revision | Modulo owns original record; reported fix needs live check |
| Creation | `writing-manuscripts/manuscripts` | Review authored report; return accepted artifact revision | Modulo owns manuscript edits; Noesis export is a snapshot |
| Externalization | `personal-sops/procedures` | Promote draft playbook; return playbook revision | Modulo owns editable SOP; Noesis rehearsal is reported |
| Internalization | `flashcards-spaced-repetition/cards` | Record unaided attempt; return pack/review revision | Modulo owns card ID, review log, and schedule; mastery unverified |
| Iteration | `decision-journal/decisions` | Record outcome/revision proposal; return cycle revision | Modulo journal edits and Noesis artifact revisions remain separate |
| Maintenance | `workspace-briefings/findings` | Review finding/health; return maintenance revision | Modulo owns briefing disposition; health is recorded only |

The deterministic FastMCP client fixture traverses Awareness discard,
Awareness → Exploration → Research, Research → Decision → Creation →
Externalization → Iteration, Problem-Solving → draft playbook,
Creation → Internalization, and Iteration → Maintenance. It checks replay,
pause/resume, inherited references, v3 projection, export, and revocation.
These are ledger/transport checks. Native artifact quality, actual Modulo
records, signed-in return navigation, second-device refresh, and user outcomes
still require representative acceptance runs.

## Native artifact journeys over MCP

`tests/unit/tools/test_intake_native_journeys_mcp.py` drives the public
knowledge-engine MCP server through `fastmcp.Client`. It creates the native
objects each mode owns, not only ledger sessions. Each tool call reopens the
DuckDB warehouse, so every step also crosses a store restart.

| Journey | Native objects and checks |
| --- | --- |
| Awareness → Discard; Awareness → Exploration → Research; no-output Exploration | Feed subscription and refresh (a duplicate GUID collapses); idempotent discard; escalation that keeps feed-item identity; an empty queue; an Exploration stopped without output; captured sources; a topic that inherits the escalated item; a reviewed-ready bundle; a verified bundle export |
| Research → Decision → Creation → Externalization → Iteration | Decision Record and Decision Support session tied to the bundle; an authored report and Creation project citing the bundle and decision (export does not authorize publication); a handoff to Externalization; a checklist promoted from the finished Creation with a rehearsed-reported guided run; a measured Iteration cycle that revises the checklist, resets trust to draft and keeps the outcome receipt |
| Problem-Solving → verified fix → playbook; Research → Internalization | Completion blocked until an observed verification; a playbook linked to the bundle concept; a hidden-answer practice review with an unaided attempt; a skill connecting practice and procedure, where self-assessment is refused |
| Maintenance | A corrected source, stale learning material, a failed rehearsal and a dead-lettered job all found. Preview-bound repair re-pins the source (the prior pin stays readable); the job is requeued; deferred items stay visible after completion |
| Fresh deployment and robustness | Discovery and preflight on an empty store; Modulo flashcard import with exact history and idempotent replay; pause, resume, duplicate and stale commands; an insufficient-evidence topic blocked from completion; source correction marks the pin superseded; export verification and tamper detection; revocation and cross-owner denial |

These journeys use an in-memory MCP transport and deterministic inputs. They
are not signed-in Modulo, second-device, live-source or user-assessed outcome
evidence, and they do not measure cadence (15 minutes of Awareness, the
Exploration time box, 30–60 minutes of Maintenance).
